# 架構與技術選型

狀態：第一版（結構圖）已實作，2026-11-05 在真實頁面驗證；第二、三版尚未開始。決定日期 2026-11-05；探針結果 2026-11-05 補入（見「探針結果」）。標「假設」的項目沒有查證，標「探針」的項目必須先在真實 ChatGPT 頁面驗證。
設計規範見 `../design/DESIGN.md`；ChatGPT 頁面結構的實測結果記在下方「探針結果」，ChatGPT 改版後需重驗。

## 目標與限制
- Chrome 外掛，只在 `chatgpt.com` 運作：右側顯示分支對話結構圖，之後補「↳ 分支」按鈕。
- 純前端、無後端、資料存瀏覽器本機；單人開發；長期好維護、不過度工程化。
- 主要風險是 ChatGPT 改版，不是效能。

## 技術選型
| # | 決定 | 替代 | 理由 | 把握 |
|---|---|---|---|---|
| 1 | Chrome 擴充功能，Manifest V3 | 無 | 目標就是 Chrome | 假設（未查證 MV2 汰除時程） |
| 2 | TypeScript | JS＋JSDoc | 選擇器與父子資料有型別，改版時編譯器指出壞處 | 高 |
| 3 | WXT | 純 Vite＋手寫 manifest、CRXJS | 提供 HMR、manifest 產生、content script 的 Shadow DOM 輔助、SPA 路由事件。綁定淺（只用在 `entrypoints/`） | 中：依據多為部落格 |
| 4 | 原生 DOM＋純 CSS（`design/`） | Preact | 節點約 40 以內，狀態只有「展開集合＋目前節點」，全部重畫即可。出現浮層、拖曳、複雜鍵盤操作時改 Preact | 中 |
| 5 | Shadow DOM（closed）放結構圖 | 前綴 class＋`all: initial` | 隔離 ChatGPT 的全域樣式。「分支按鈕」是否放入需先驗證 | 高：探針 3 通過（點擊不清選取、按鍵不被吞、字型繼承） |
| 6 | `chrome.storage.local` | IndexedDB | 資料很小、可跨分頁同步。不用 `localStorage`（同網域腳本讀得到） | 高 |
| 7 | 第一版只讀頁面 DOM | 呼叫 `/backend-api` | 內部 API 需登入憑證、未公開、風險較高。代價：只知道造訪過的對話 | 中（條款風險未查證） |
| 8 | Vitest（純邏輯）＋選擇器探針 | Playwright | 登入無法自動化，對 chatgpt.com 做 E2E 不划算。快照只能證明舊版沒壞，所以要另寫能實測選擇器的探針 | 中 |

不用 Rust／WebAssembly：工作量是約 40 個節點的 DOM 讀取與渲染，瓶頸在 DOM。WebAssembly 不能直接操作 DOM，需 JavaScript 當橋，且多一套工具鏈。常說的 Rust 多半是打包器、編譯器等工具，已經替你用 Rust 寫了。

不用 Plasmo：多個來源指出核心已久未發佈、仍有人詢問是否還在維護（第三方說法，無官方聲明）。

## 專案結構（沿用 WXT 預設）
```
entrypoints/content.ts      入口：只負責串接，不放邏輯（WXT 只出現在這一層）
lib/chatgpt-dom.ts          唯一知道選擇器的地方；ChatGPT 改版只改這裡
lib/tree.ts                 純函式：由「對話 ID＋父 ID」建樹；可單元測試
lib/store.ts                chrome.storage.local 的讀寫
lib/ui/branch-map.ts        結構圖渲染；樣式用 design/branch-map.css
design/                     tokens.css、branch-map.css、DESIGN.md
docs/                       本文件
tests/                      單元測試；tests/fixtures/ 放去除對話內容的 DOM 快照（附取樣日期）
prototype/                  前端模擬原型，僅作參考，不進外掛
```
規則：選擇器只出現在 `chatgpt-dom.ts`；`tree.ts` 不依賴頁面；樣式只用 `--bc-` 變數與 `bm-` 類別。

## 資料
每條對話只存：`id`、`parentId`、`title`、`seenAt`，每條一個 key（`bc-c:<id>`），讓多個分頁同時寫不同對話時不互相覆蓋。偏好（是否收起）存在 `bc-prefs-v1`。外掛開關存在 `bc-enabled`（預設開；清除紀錄不改它）。
- 只保存有分支關係的對話（有父，或被當成父）；一般對話不保存。不存訊息內容。外掛不在無痕視窗執行（`incognito: not_allowed`）。選項頁可清除全部資料。
- ID 一律先驗證格式（UUID，草稿多 `local-chatgpt:` 前綴）；格式不對、%編碼錯誤都當成沒讀到。讀 storage 時也驗證每筆的形狀。
- `id` 取自網址 `/c/<id>`；`parentId` 取自「接續自」連結。現在每條分支只有一條，指向直接父；祖先鏈靠逐層造訪串起來。
- 在分支還是草稿（`/c/local-chatgpt:<uuid>`）時就記下父對話，網址換成正式 ID 時再對應過去。剛送出第一則訊息的那一刻，用正式 ID 讀不到父連結（重新整理後正常）。
- 讀不到父對話時不特別處理：那條先當成獨立節點，之後讀到再接上（使用者決定）。
- 「這次沒讀到」不等於「沒有父」：只新增關聯，不因為某次讀到空值就刪除或覆寫已存的 `parentId`。
- 草稿 uuid 和正式 uuid 不同（實測 `local-chatgpt:33248c2a…` → `6aec8779…`）。草稿只放記憶體，不寫入 storage。只有「在這個草稿裡按了送出」（輸入框有文字，或送出鈕可按）、60 秒內網址換成**送出那一刻左欄還沒有**的正式 ID，而且中間使用者沒有自己點連結、按上一頁或在輸入框外按 Enter，才把父關係交給它；既有對話不會被接成分支。
- 結構圖標題以左欄目前顯示的為準（改名立刻反映）；左欄沒載入時用存下的標題。storage 只在目前這條的標題變了時更新，而且只有「本分頁看到的標題變了」或第一次看到且和已存的不同時才寫入，避免兩個分頁輪流蓋寫。
- 從其他分頁收到的變動只更新記憶體，不寫回。
- 只記造訪過的對話。對話在 ChatGPT 被刪除時，改成墓碑（只留 ID、父 ID、刪除時間，清掉標題）；結構圖跳過墓碑，子分支顯示在上一層。子分支的父 ID 從不改寫，所以判斷錯了也能完整復原：之後打開那條對話（而且是在刪除之後才打開的頁面），就拿掉墓碑。葉子也留墓碑（開著舊頁面的分頁才不會把它存回去）；沒有子分支的墓碑放 30 天後清掉，根因此不再有分支關係也一併清掉。復原只限刪除之後才載入的頁面（內容穩定 1 秒）：刪除前就開著的分頁可能顯示快取內容，不能讓它把刪掉的救回來；誤判的話，重新整理後打開它就會恢復。寫入用 Web Locks 讓所有 ChatGPT 分頁依序「讀、檢查、寫」，避免一個分頁把另一個分頁剛寫的墓碑蓋掉。沒存過、但被當成父的對話（在 R 開分支時 R 還沒有子分支）也能被標成刪除。選項頁按清除後，開著的分頁在換到下一條對話前不再寫入。
- 判斷「已刪除」要有明確證據，其餘一律不判：
  - **使用者確認刪除**：打開某條的選單（左欄那列的選單鈕，或頂列的「對話操作」＝目前這條）→ 按危險樣式的選單項目 → 在確認對話框「點擊」危險樣式的按鈕（按下後拖離不算）；之後 10 秒內，確認當下看得見的那條左欄連結消失，或刪的是正在看的這條、ChatGPT 自己把頁面帶離（首頁或專案頁；確認後使用者自己點走的不算）。用鍵盤打開的選單不追蹤（記下的對話不可信）。按取消、Esc、或點對話框以外的地方都作廢。判定後寫入 storage，所有分頁的結構圖同時拿掉它，舊分頁就不會再點到它而看到「沒有權限」。（實測 2026-11-06：確認框是 `role="dialog"`，「刪除對話」按鈕帶 danger 樣式，「取消」「關閉對話框」沒有；按 Esc 可取消）
  - 已知漏判、交給後備：用鍵盤選刪除（事件可能不是 isTrusted）、設定裡的「刪除所有對話」、封存清單裡的刪除、其他裝置的刪除。
  - 推薦做法的評估（2026-11-06，乾淨子代理）：不改用包裝 fetch 看刪除請求（改名、封存、刪除是同一個網址，要讀請求內容才分得出來，違反只觀察結構，審查也會當成攔截流量），也不用登入狀態呼叫 ChatGPT API（要碰憑證）。
  - 打開已存的對話，內容一次都沒出現、使用者也沒有點擊／按鍵／上一頁，就被導回首頁 `/`，而且左欄正常顯示、裡面沒有它（左欄還沒載入就等，最多 15 秒）（ChatGPT 對不存在的對話就是這樣，實測 2026-11-06；左欄沒顯示時可能是登出或載入失敗，不判斷）。也看頁面一開始載入的網址，因為 ChatGPT 可能在外掛啟動前就導回首頁。
  - 不用「左欄連結消失」或「被導回首頁」單獨當證據：改名、封存、收起專案資料夾、登入過期都會造成同樣的現象。
  - 在其他裝置刪除的，這台看不到刪除動作，只能等打開時判斷；要完全避免得用登入憑證去問 ChatGPT 伺服器，不做。
- 已存的父對話不會被之後讀到的不同值覆寫。

## 第一版的顯示規則
- 工具列在 manifest 明確宣告 `action.default_icon`（16／32），保持不同網站下圖示原色。未宣告 action 時曾實測 ChatGPT 黑底、YouTube 灰化；宣告並重新載入後兩站均黑底白線（2026-11-06）。不新增 host 權限、popup 或點擊處理器；content script 仍只注入 ChatGPT。
- 只有一條（沒有分支）時不顯示結構圖：一個點沒有要表達的東西。
- 固定寬 280px，從頂列下方開始。讓位：在 `[data-request-input-activity-root]` 與 `[data-thread-scroll-footer]` 加 `padding-right`，ChatGPT 會自己把對話欄重新置中。不能縮 `main`：它有 `clip-path`，會把頂列的「分享」等按鈕裁掉。
- 可用寬（視窗右緣減 main 左緣）不到 280+640 時，或讓位用的元素找不到時：自動收起，按開時覆蓋在對話上，不讓位。
- 工具列彈出視窗有一個開關（Branch mode）：關閉時解除所有頁面監聽、拆掉結構圖、還原版面，不讀頁面、不寫資料（連過期墓碑都不清），頁面上不留外掛的元素；只留著 storage 的監聽，等開關打開。即時生效，不用重新整理。進行中的刪除判斷與草稿轉正一律作罷；重新開啟時那次造訪不拿來判斷刪除；關閉期間刪除的對話，要等下次打開那條才移除。
- 寫入在 Web Lock 裡讀最新紀錄再合併：保留 storage 已有的父關係與第一次看到的時間；請求之後被清除、或外掛已關閉，就不寫。
- 一顆收合鈕，放在頂列按鈕群（`[data-app-shell-header-obstacle]`）左邊；收起狀態全域記住。找不到頂列按鈕群時整個不顯示。ChatGPT 原生右側面板打開時也不顯示。
- 跟著 ChatGPT 的淺色／深色（看頁面的 `color-scheme`）；淺色 token 的主要顏色實測自 ChatGPT（2026-11-06）。CSS 打包時屬性值引號會被拿掉，替換成 `:host(...)` 的規則要容許沒有引號。
- 結構沒有變化時不重畫，避免串流回答時一直閃。
- 讀不到目前對話超過 10 秒時，在主控台警告一次（ChatGPT 可能改版）。

## 交付順序
1. 結構圖：只讀已存在的分支關係，不加按鈕。
2. 「↳ 分支」按鈕：觸發原生分支。
3. 選字帶引用到新分支。

## 探針結果（2026-11-05，繁中介面、深色模式）
| # | 項目 | 結果 | 證據 |
|---|---|---|---|
| 1 | 父連結與訊息 UUID | 通過（短對話）；長對話有條件失敗 | 3 條 × 10 次站內切換＋捲動：30/30；3 條 × 10 次重新整理：30/30（0.25–1.25 秒）。13 回合長對話同時只渲染 4–6 回合 |
| 2 | 程式觸發原生分支＋帶入選取 | 通過 6/6 | 網址變 `/c/local-chatgpt:…`；輸入框內容等於選取文字（開頭空白會被去掉）；送出鍵啟用 |
| 3 | Shadow DOM 按鈕 | 通過 | 真實點擊後選取保留（有無 `mousedown` preventDefault 都是）；在 Shadow 內輸入框打字與 Esc 不被搶；字型繼承 body |
| 4 | 未造訪的子分支 | 左欄掃描不可靠 | 3 條分支中，兩層分支的候選父有 2 個（同標題兄弟），只有造訪才確定 |

選擇器（都不靠介面文字，只放 `lib/chatgpt-dom.ts`）：
- 目前對話：`[data-chatgpt-selection-conversation-id="<網址 id，需 decodeURIComponent>"]`，往上找 `.thread-scroll-container` 當範圍。站內切換後舊對話的 thread 只是 `display:none`，不鎖定網址 ID 會讀到舊對話。
- 回合：`[data-turn-key]`。訊息 UUID 只在助理回答上。
- 使用者訊息本文：`[data-user-message-bubble]`。`[data-conversation-role]` 是給螢幕閱讀器的隱藏標題（內容是「你說：」之類），不是訊息。
- 父連結：範圍內的 `[data-turn-key] a[href^="/c/"]`，放在分叉那一回合裡。只取第一個，並排除訊息本文（`[data-user-message-bubble]`、`[data-chatgpt-selection-conversation-id]`）裡的連結。
- 「…」選單：回合內的 `button[aria-haspopup="menu"]`，用 `svg use` 的 href 含 `ellipsis-horizontal` 辨識；用 `pointerdown` 開啟。
- 分支子選單：`[role=menuitem][aria-haspopup=menu]`，用 `branch` 圖示辨識；`ArrowRight` 開啟。
- 「在新對話中建立分支」：子選單兩項**無圖示、屬性相同，只能靠位置**；目前是最後一項，第一項是「在工作模式中建立分支」（是否收費未知）。
- 輸入框：可見的 `.ProseMirror[contenteditable="true"]`，用 `focus()` 加 `execCommand('insertText')` 放入文字。

失敗條件：
- 長分支的分叉回合不在畫面附近時，因為虛擬捲動，父連結不在 DOM（依結構推論，未用長分支直接驗證）。
- 剛送出第一則訊息、還沒重新整理的那一刻，用正式 ID 讀不到父連結。

## 風險與未決
- ChatGPT 改版造成選擇器失效；「接續自」文字有在地化，不能靠文字比對。同一天內已觀察到改版：兩層分支從「每層祖先一條」變成只剩直接父，使用者提問不再有訊息 UUID，子選單順序也和先前記錄相反。
- 第二版的按鈕靠「子選單最後一項」選「在新對話中建立分支」。順序一變就可能誤入工作模式（是否收費未知），需要防護。建議做法：外掛只打開選單，把焦點停在該項，最後一下由使用者自己按；若這樣只省一兩次點擊，就重新評估第二版是否必要。
- 不掃描左欄「分支 · 」標題補沒造訪的分支：前綴是在地化文字，同標題的兄弟分支無法分辨父對話；改名、左欄只載入最近項目也會漏（後兩項是推論）。
- 上架 Chrome Web Store 與 ChatGPT 服務條款的影響，未查證。
